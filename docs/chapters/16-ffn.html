IV. The rest of the block · Chapter 16

Where most of the parameters actually live

Attention gets the attention, but the feed-forward network holds roughly two thirds of the weights and behaves like a key-value memory.

Assumes 03, 05.

In 2021, Mor Geva, Roei Schuster, Jonathan Berant and Omer Levy published a paper titled "Transformer Feed-Forward Layers Are Key-Value Memories." The title made a claim about mechanism, and it landed on the part of the Transformer that most of the field had treated as plumbing. Attention was where the ideas were, where the papers were, where the interpretability work went. The feed-forward network was the thing you appended to attention because a block needed a second sublayer.

Then you count the matrices, and the emphasis looks badly placed.

Start with the block. A Transformer of depth L carries a residual stream, a vector of width d that runs from the embedding layer to the unembedding. Each sublayer reads that vector, computes something, and adds the result back. Attention lets positions exchange information; it projects the stream into queries, keys and values, mixes across positions, and writes the mixture back. The feed-forward sublayer does no mixing. It reads one position's vector, transforms it in place, and adds the result back at that same position. At the end, the final stream state is multiplied by an unembedding matrix of shape d by V, where V is the vocabulary size, and the resulting scores become the logits that pick the next token.

A standard block holds two sublayers. Attention has four projections of size d by d, for queries, keys, values and the output mix, so 4d² parameters. The feed-forward sublayer takes the d-dimensional residual vector, expands it to an inner width m, applies a nonlinearity, and contracts back to d. Two matrices, d by m and m by d, holding 2dm entries. With m = 4d, that pair holds 8d², twice the attention sublayer, in every layer, at every scale. Layer norms and biases add a few d each, which is rounding error against d² terms.

Across a model, the feed-forward share of the parameters is

8Ld² / (12Ld² + cVd)

where c is 2 when the embedding and unembedding matrices are separate and 1 when the weights are tied. Take d = 4096, L = 32 and V = 128,000. Attention comes to 32 × 4 × 16,777,216 = 2,147,483,648 parameters. The feed-forward pair comes to 32 × 8 × 16,777,216 = 4,294,967,296. Untied embeddings add 2 × 128,000 × 4096 = 1,048,576,000, for a total of 7,491,026,944 and a feed-forward share of 57.3 percent. Tie the embeddings and one matrix is shared, so the embedding term halves to 128,000 × 4096 = 524,288,000, and the total drops to 6,966,738,944, lifting the share to 61.7 percent. The fraction climbs toward two thirds as d grows, because the per-layer terms scale with d² while the embedding term scales with d.

The four-times expansion is old. Vaswani and colleagues set the inner width to four times the model width in "Attention Is All You Need" in 2017, and their Table 3 varies individual hyperparameters—including d_ff 2048 vs 4096 and d_model 512 vs 1024—and reports BLEU/perplexity alongside parameter counts, not perplexity per parameter. Table 3 mostly varied model and inner widths together, but row (A) did test the ratio in isolation by raising d_ff from 2048 to 4096 at d_model = 512; that 8× inner width performed slightly worse than the 4× base (PPL 4.41 vs. 4.33, BLEU 26.0 vs. 26.4), so the 4× choice was not strongly established by that table. GPT-2 in 2019 and GPT-3 in 2020 kept it. T5, from Raffel and colleagues in 2019, kept four times in its base and large sizes but widened the inner layer to sixteen times at 3B parameters and sixty-four times at 11B, buying capacity with parameters rather than with depth.

The gated variants that Shazeer described in 2020 change the count. A gated linear unit multiplies the expanded vector by a second projection of the same shape, so the sublayer holds three matrices of d by m instead of two. To keep the parameter budget at 8d², the inner width has to shrink to 8d/3, about 2.67d. That is where LLaMA's inner width comes from. With d = 4096, 8d/3 is 10,922.67, and LLaMA rounds it up to 11,008, a multiple of 256. The ratio is 2.69, and the parameter count matches a plain four-times FFN. The four-times rule is really a rule about 8d² of parameters per layer (see the mixture-of-experts chapter for where that arithmetic goes next), and the inner width is whatever satisfies it.

What does the pair compute? Take one token's residual vector, call it x. The first matrix has m rows, each a direction in the same d-dimensional space as x. Row i produces a scalar s_i = k_i · x, the dot product of that row with x, which measures how much the token's state points along that direction. Geva's group called those rows keys. A nonlinearity φ then acts on each scalar separately. In the original Transformer φ was ReLU, so any s_i below zero became exactly zero and that slot contributed nothing to the output. Modern blocks usually use GELU, which attenuates small negative scores instead of zeroing them, or SwiGLU, which multiplies the expanded vector by a second gated projection before the contraction. Under ReLU, roughly half the slots are silent for a given token. Under GELU, almost all of them contribute something, most of it tiny.

The second matrix supplies, for each of the m hidden units, a vector v_i in d-space. Those are the values. The sublayer's output is

y = Σ_i φ(k_i · x) v_i

a weighted sum of value vectors, with the weights set by how well the token matched the corresponding keys. That is a memory read. The keys are addresses, the values are contents, and the read is soft. A slot whose key aligns strongly with x contributes a large multiple of its value vector; a slot whose key is orthogonal contributes nothing; a slot whose key points the other way is suppressed by the nonlinearity. Each layer has m slots. A model with 32 layers and m = 16,384 has 524,288 of them, and the residual stream carries the sum forward to be read again by the next layer's keys.

Geva and colleagues followed up in 2022 by projecting each key and each value into vocabulary space, multiplying by the unembedding matrix and reading off the tokens with the largest scores. A key whose top projections are "the", "a" and "an" is a determiner detector, and it tends to fire when the residual at the current position carries determiner features, which may come from a determiner at that position or nearby (e.g. the previous token). A key that projects onto "France", "Paris" and "Europe" fires on country names. That projection gives an operational definition of a key pattern, the set of input contexts that maximize k_i · x, which you can find by gradient ascent on the dot product or by scanning a corpus for the contexts where the slot's activation is largest. The values, projected the same way, tend to promote words related to the entity under discussion. The pairing is what you would design if you wanted a lookup table keyed on context and returning content.

This is where factual knowledge sits, and the causal evidence is specific. Meng, Bau and colleagues published ROME in 2022. Their procedure runs the model twice. The clean run uses a prompt like "The Eiffel Tower is located in" and assigns high probability to "Paris". The corrupted run replaces the subject tokens with noise, and the probability of "Paris" collapses. Then, for each layer and each token position, they take the corrupted run and overwrite one component's output with the value it had in the clean run, letting the rest of the network run forward. The score is the probability the model then assigns to the correct answer token, averaged over a set of facts and normalized against the clean and corrupted baselines. Plotted as a heatmap over layers and positions, the recovery concentrates at the last token of the subject and peaks in the middle layers, and the component that carries most of it is the feed-forward block. Restoring attention outputs at the same position recovers less, and the attention effect sits at the final token position in later layers, where the model moves the answer into place.

The mechanism explains the result. Attention moves information between positions; by the time a subject like a country name has been resolved into the residual stream at its own position, the attribute lookup is a local operation. The feed-forward block is the only sublayer that transforms a single position

Editing follows from the structure. If a fact is a key-value pair, you can change the value by writing to the second matrix. ROME computes a rank-one update. Let k be the key direction you want to steer, taken as the FFN’s intermediate key vector at the subject’s last token—the input to the down-projection matrix—averaged over many prompts. and let v be the vector you want the sublayer to add to the residual. The current output along that direction is W k, where W is the down-projection matrix. The update is

ΔW = (v − W k) kᵀ / (kᵀ k)

and after the write, (W + ΔW) k = W k + (v − W k)(kᵀ k)/(kᵀ k) = v. The key now returns exactly the value you asked for, which is what makes the memory addressable in the first place. The outer product (v − W k)kᵀ has rank one, so every row of the update is a multiple of k and the write changes the matrix only along one direction in input space.

The size of the write is small. With d = 4096 and m = 16,384, W holds 67,108,864 entries. If the key has norm 20 and the desired change has norm 1, the update has Frobenius norm 1/20 = 0.05, spread across those 67 million entries, so the root-mean-square change per entry is 0.05/8192 ≈ 6.1 × 10⁻⁶. The layer is chosen by sweeping candidates and measuring the edit's success rate on held-out prompts; the paper reports the best results in a middle band of layers, which matches where the causal trace peaks.

The fragility comes from superposition. In d dimensions there are at most d mutually orthogonal directions, and a layer has m = 4d keys, so the keys cannot all be mutually orthogonal; many must have nonzero cosine similarity and therefore interfere. Two keys with cosine similarity c interfere. After the edit above, the output for a second key k' changes by (v − W k)·c, because the update's effect on k' is (v − W k)(kᵀ k')/(kᵀ k). At c = 0.3 and equal key norms, a neighbouring key's readout shifts by 30 percent of the edit vector. Currency facts illustrate it. "The currency of France is" and "the currency of Germany is" share the pattern "the currency of X is", so their keys point in similar directions, and rewriting the franc entry drags the mark entry with it. MEMIT, from the same group later in 2022, spreads thousands of edits across several layers to keep any single layer's interference below the point where neighbours drift.

Quantization has the same shape of implication, from the other direction. Because the feed-forward matrices hold most of the bytes, they are where quantization saves the most memory; where quantization errors do the most damage depends on each component’s sensitivity, and the feed-forward layers are not necessarily the most sensitive. Group quantization stores each weight as a b-bit integer q and reconstructs it as w ≈ s·q, with one scale s shared by a run of G consecutive weights. The scale is set from the largest magnitude in the group. A group of 128 weights at 4 bits with a 16-bit scale costs 4 + 16/128 = 4.125 bits per weight. Shrink the group to 32 and the cost rises to 4.5 bits; widen it to 256 and it falls to 4.0625. Finer groups track the local range better and pay more overhead.

The failure mode is a single large weight inside a group. Take a group of 128 weights whose typical magnitude is 0.02 and one outlier at 0.5. With 4-bit signed integers spanning −8 to 7, the scale must be 0.5/7 ≈ 0.0714. A weight of 0.02 then quantizes to round(0.02/0.0714) = round(0.28) = 0, and it is reconstructed as zero. Without the outlier, the largest magnitude might be 0.03, giving a scale of 0.03/7 ≈ 0.00429. The same weight quantizes to round(0.02/0.00429) = 5 and is reconstructed as 0.0214, an error of 7 percent. Every small weight in that group suffers the same fate.

Outlier weights are common enough that the quantization literature organized around them. LLM.int8(), from Dettmers and colleagues in 2022, found that a handful of feature dimensions in large Transformers carry values an order of magnitude above their neighbours, and handled those dimensions in higher precision. AWQ in 2023 singles out a small fraction of weights, chosen by activation magnitude, for gentler treatment, and its authors report that protecting that fraction accounts for most of the quality gap at 4 bits. GPTQ, also from 2023, takes a different route: it quantizes every weight, using second-order information from activations to compensate for the quantization error column by column These methods protect outlier dimensions or salient weights across the model’s linear layers rather than singling out one matrix; the feed-forward down-projection is nonetheless a sensitive site, because its output is written straight into the residual stream An error δy there becomes an error in the stream that every later sublayer reads. It is projected by W_Q and W_K into the next layer, and finally in the logits as w·δy for each unembedding row w. The stream also holds the attention outputs and the token embedding, so δy competes with them rather than replacing them, but attention does carry δy to other positions through the value vectors, but the error at position i itself is not averaged away, because the feed-forward output is written at one position and read at that same position by the next feed-forward sublayer.

The bandwidth argument points the same way. Decode reads the whole weight set once per token, because each token needs every matrix. On this book's engine, four prompts of 400 tokens each run sequentially in 27.1 seconds, which is 1,600 tokens at 59.1 tokens per second. The same four prompts fired concurrently finish in 15.1 seconds, or 106.2 tokens per second, a factor of 1.80. Each machine carries 273 GB/s of LPDDR5X bandwidth shared between CPU and GPU. Divide 273 by 59.1 and a single stream has a budget of 4.6 GB of streaming per token if the decode loop were purely bandwidth-bound on one machine. At a feed-forward share near 60 percent, about 2.8 GB of that is feed-forward weights. Shard the weights across both machines and the per-token budget doubles to 9.2 GB.

The concurrency number says the loop is not purely bandwidth-bound. Batching four streams lets one read of the weights serve four tokens, so aggregate throughput should approach four times the single-stream rate if weights dominated the cost. It reaches 1.80 times. The rest of the per-token cost is the KV cache read, and with a mean prompt length of 130,659 tokens in the sampled window, that read is enormous. Prefill runs at 39,237 tokens per second because it is matrix-matrix work that reuses each weight across many tokens, though at these 130k-token prompts quadratic attention dominates the prefill cost, so this rate is context-length dependent. Decode runs at 59.1 because it is matrix-vector work that reuses each weight once.

Here is the part worth arguing about. The four-times ratio is a default that most papers no longer justify, but it is not arbitrary. It sets how much of the parameter budget goes into memory capacity rather than into token mixing, and Vaswani. Because the parameters live in the feed-forward block, the obvious way to add capacity without paying per-token compute proportional to the added capacity is to add many feed-forward blocks and route each token through only a few of them—capacity grows with the number of experts, while per-token compute grows only with the routing fan-out. Shazeer's sparsely-gated mixture-of-experts in 2017 and Switch Transformer in 2021 are that move, and the sparse models that followed, from GShard in 2020 to Mixtral in 2023, keep the shape.

The arithmetic is plain. Take d = 4096 and eight experts per layer, each a plain four-times FFN holding 8d² = 134,217,728 parameters. The layer then holds 1,073,741,824 feed-forward parameters, eight times the dense layer, while a top-2 router sends each token through two experts, so per-token compute is 2 × 8d² = 268,435,456 multiply-adds against 134,217,728 for the dense layer. Capacity grows eightfold and compute doubles. Attention got the name on the architecture, and the feed-forward block got the parameters, with a router of about 32,768 parameters (plus bias) deciding which of them a token reads.
