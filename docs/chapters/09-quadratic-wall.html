II. Attention · Chapter 09

The cost that defines the field

Every architectural decision in modern inference is a response to the fact that attention cost grows with the square of sequence length.

On a server holding 111.5 GB of unified memory, a request arrives carrying a prompt of 130,659 tokens. That figure is the mean prompt length across 98 requests, derived from the engine's counters as 12,804,579 prompt tokens divided by 98. The engine has a shared KV pool of 262,144 positions and four concurrent streams. Admission reserves each stream an equal share of the pool, then subtracts the reply budget and round-batch overhead: 262,144 / 4 = 65,536; 65,536 − 32,768 − 16 − 2 = 32,750. The prompt does not fit inside that ceiling: 130,659 tokens is roughly four times the 32,750-token limit, so admission would reject or chunk the request Now attention does its work.

A transformer block stacks an attention sublayer with a feed-forward network. The quadratic cost lives in the attention sublayer. For each token, the model produces a query vector, a key vector, and a value vector. For token i, attention scores its query against the key of every token j ≤ i (causal masking), so the score matrix is lower triangular with n(n+1)/2 entries; using n² as an upper bound for the quadratic scaling argument. The score is a dot product. Softmax turns the row of scores into weights that sum to one. The output for token i is the weighted sum of all value vectors. The cost comes from the phrase "every token j." For a sequence of length n, the score matrix has n rows and n columns. At 130,659 tokens, the entry count is 130,659 squared, or 1.707 × 10^10. Every entry requires a dot product of length d, the head dimension. Take d = 128. The score computation costs 1.707 × 10^10 × 128 = 2.185 × 10^12 multiply-adds per head per layer. The value aggregation costs the same again. That is the quadratic term.

Store that matrix as a dense fp16 array and the arithmetic becomes concrete. Each entry takes two bytes. 1.707 × 10^10 entries × 2 bytes = 34.1 GB for one head in one layer. The on-chip SRAM of a GPU is measured in tens of megabytes, so the matrix is roughly a thousand times larger than the memory that feeds the compute units. It is also about 31 percent of the 111.5 GB the engine holds, since 34.1 / 111.5 comes to 30.6. Multiply by the head count and the layer count and the product passes the budget many times over — which is why no production kernel ever materializes this matrix; attention is computed in fused, streaming tiles. The n² figure is a compute-cost illustration, not a memory budget. The wall the engine actually hits is the KV cache: at 130,659 tokens the per-stream KV footprint, its bandwidth demand, and allocator fragmentation across four concurrent streams are what bind admission, not score storage

The first response to the wall was a change in the memory schedule. The math stayed the same. Standard attention materializes the score matrix in HBM, the large but slow memory attached to the GPU. It writes scores, reads them back for softmax, writes probabilities, reads them back for the value multiply. Each pass moves n squared entries through an HBM bus delivering roughly 1.5–3.3 TB/s on datacenter GPUs that is far slower than the SRAM feeding the compute units. Tri Dao and colleagues introduced Flash Attention in 2022. The idea is to tile the score matrix. Load a block of queries and a block of keys into SRAM, compute the scores for that tile, apply softmax incrementally, multiply by the corresponding values, and write only the output. The n squared matrix never exists in HBM. The backward pass recomputes the tiles instead of storing them. The arithmetic is identical to standard attention. The memory footprint is linear in n. HBM traffic is still quadratic in n for a fixed tile size, but with a much smaller constant: it drops to O(n^2/M) for SRAM size M, because K and V tiles are re-read for each query tile rather than materializing the full score matrix Flash Attention is exact. It does not trade recall. It refuses to pay the HBM tax.

The incremental softmax is the part that makes the tiling work. For a full row, softmax needs the maximum score to subtract before exponentiating, and the sum of exponentials to normalize. When you process a row in tiles, you do not know the global maximum until you have seen every tile. Flash Attention keeps a running maximum m and a running sum l. Start with m = −∞ and l = 0. For each tile, compute the tile maximum m_tile. The new running maximum is m_new = max(m_old, m_tile). Rescale the accumulated sum and output: l_new = l_old × exp(m_old − m_new) + Σ exp(s_tile − m_new); O_new = O_old × exp(m_old − m_new) + Σ exp(s_tile − m_new) × v_tile. The factor exp(m_old − m_new) is at most 1, so the rescale never overflows. At the end, divide O by l. The result is numerically identical to the full softmax, up to the rounding of the exponentials.

Work through two tiles with numbers. Suppose the first tile yields scores [2, 4] and the second yields [6, 8]. After tile one, m = 4, l = exp(2−4) + exp(4−4) = 0.135 + 1 = 1.135. After tile two, m_new = 8. Rescale: l = 1.135 × exp(4−8) + exp(6−8) + exp(8−8) = 1.135 × 0.0183 + 0.135 + 1 = 0.0208 + 1.135 = 1.156. The full softmax over [2,4,6,8] gives denominator exp(2−8)+exp(4−8)+exp(6−8)+exp(8−8) = 0.00248 + 0.0183 + 0.135 + 1 = 1.156. The running sum matches. The output accumulates the same way, with the same rescale applied to the partial value sum.

Dao's contribution was to fuse that recurrence with the value multiply and the backward pass so that the score matrix never touches HBM. The backward pass recomputes the score and probability tiles from Q and K, using the saved logsumexp and output for gradient scaling. which costs a second pass over the same arithmetic but saves the memory. The tile order matters for rounding, not for the mathematical result. Summing in a different order changes the last bits of the floating-point result, and the recomputation in the backward pass uses the same order so the gradients are consistent with the forward pass.

Sparse attention took a different route. Child, Gray, Radford and Sutskever introduced the Sparse Transformer in 2019. Longformer followed in 2020 from Beltagy, Peters and Cohan, and BigBird also in 2020 from Zaheer and colleagues. The mechanism is a mask. Each token attends to a local window of nearby tokens and to a small set of strided or global tokens. The score matrix still has n squared entries in principle, but most are masked out and never computed. Take a window of 4,096. At n = 130,659, the quadratic cost is 1.707 × 10^10 entries; the windowed cost is 130,659 × 4,096 = 5.35 × 10^8, a 32-fold reduction. The trade is recall. A token can no longer attend to every other token directly. Information must hop through intermediate tokens. For exact retrieval of a fact placed far away, that hop loses precision. The mask is a bet that most long-range interactions are mediated by local structure.

Linear attention replaced the softmax with a kernel feature map. Katharopoulos and colleagues proposed this in 2020. Define phi as a positive feature map applied elementwise, for example phi(x) = elu(x) + 1. Instead of computing softmax(Q K^T) V, compute phi(Q) (phi(K)^T V), divided elementwise by the normalizer phi(Q)·Σ_j phi(K_j) — the row sums of phi(Q) phi(K)^T — which is what makes the result a weighted average rather than an unnormalized sum that grows with n, divided elementwise by the normalizer phi(Q)·Σ_j phi(K_j) — the row sums of phi(Q) phi(K)^T — which is what makes the result a weighted average rather than an unnormalized sum that grows with n. Associativity does the work: phi(K)^T V is a d by d matrix that can be computed once and reused for every query. The cost becomes O(n d^2) instead of O(n^2 d). With d = 128, the crossover is at n = 128. At n = 130,659, linear attention costs 130,659 × 128^2 = 2.14 × 10^9 operations, against 2.185 × 10^12 for the quadratic form, a thousand-fold difference. The trade is exactness. Softmax produces a sharp, competitive weighting; a kernel feature map produces a smoother weighted average. The model loses the ability to focus precisely on one token. That loss follows from the construction.

State-space models are the most recent subquadratic family. S4, from Gu, Goel and Ré in 2021, and Mamba, from Gu and Dao in 2023, use a recurrence with a fixed-size state. The mechanism is a linear recurrence over the sequence: h_t = A_t h_{t−1} + B_t x_t, y_t = C_t h_t. Each token updates the state, and the output is read from the state. The recurrence itself is linear-time at inference, and Mamba’s selective scan is O(n); original S4 training uses an FFT convolution at O(n log n), so the family is subquadratic rather than uniformly linear The trade is memory. A fixed-size state cannot store every key and value. It must compress. For tasks that need exact recall of a token from 100k positions ago, a fixed state will forget. Mamba adds input-dependent selection: A_t, B_t and C_t are functions of x_t, so the state can decide what to write and what to drop at each step. That is a real improvement over the fixed linear recurrence of S4, but it does not recover exact recall.

The honest comparison is this. Flash Attention is exact, so it does not trade quality for speed. Sparse attention, linear attention and state-space models trade exactness or recall for asymptotics. That trade is sometimes worth it. The field's dominant response to the quadratic wall has been to keep exact attention and optimize the memory hierarchy around it. Linear attention is simpler and asymptotically cheaper, though constant factors and kernel maturity mean it is not always faster at short or medium context lengths It has not displaced exact attention for quality-critical long-context work. The wall is still there. We have learned to tile around it.

The KV cache is the other cost. It grows linearly with sequence length, not quadratically, but it dominates memory at long context. The engine's pool of 262,144 positions is shared across four streams. Raising it to the model's native 1,048,576 positions would cost 0.68 GiB per rank. The configuration script records 0.9 GiB per 1,048,576 positions, which is 921.6 bytes per position across all layers. Raising the pool by 786,432 positions costs 786,432 × 921.6 bytes = 724.8 MB, or 0.675 GiB, rounded to 0.68. That is the linear cost. The quadratic compute cost appears in attention both during prefill (quadratic in prompt length) and during decode, where each generated token reads the full KV cache, so total decode cost is also quadratic in context length Both are real.

The engine also uses a prefix cache. A prefix cache hashes the prompt prefix, looks it up in a radix tree of stored KV blocks, and reuses the matching blocks instead of recomputing them. In the sampled window, 95.9% of prompt tokens were cached, a hit rate derived as 12,285,952 cached tokens divided by 12,804,579 queried tokens. At the measured prefill rate of 39,237 tokens per second, those cached tokens removed 12,285,952 / 39,237 = 313 seconds of prefill time. That figure is the counterfactual: the time the engine would have spent recomputing those tokens. Caching attacks the quadratic cost by not recomputing what you already have. It does not change the asymptotics, but it changes the constant.

The decode side has its own cost. Prefill processes the whole prompt in parallel and pays the quadratic term once. Decode generates one token at a time and attends to the KV cache. For each new token, the query scores against n cached keys, which costs O(n d) per head per layer, not O(n^2 d). The KV cache itself is 2 × n × d × layers × bytes. At n = 130,659 and d = 128, that is 2 × 130,659 × 128 = 33.4 million values per layer, or 66.9 MB in fp16 per layer. Multiply by the layer count and the cache dominates the memory budget at long context. The engine's 262,144-position pool is sized for that, not for the score matrix.

The pool is the binding constraint. At 262,144 positions shared across four streams, each stream gets 32,750 tokens after the reply budget and overhead. The model's native window is 1,048,576 positions. Closing that gap costs 0.68 GiB per rank, which is cheap in memory terms and expensive in scheduling terms, because the admission reservation has to hold the line for every stream.
