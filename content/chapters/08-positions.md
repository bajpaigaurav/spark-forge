## Attention has no idea where it is

### Unmasked attention is permutation-equivariant

Take "the dog bit the man", run it through one bidirectional self-attention layer, then run "man the dog the bit" through the same layer. Compare the two outputs. Every vector from the first run appears in the second. The set is identical. Only the ordering changed.

That follows from the arithmetic for a layer with no mask. For token i the layer produces a weighted average of value vectors, where the weight on token j is the softmax over q_i · k_j / √d_k across all j. Permute the input by some π and every query, key and value travels with its token. The collection of dot products is the same collection, so the softmax normalises over the same numbers and assigns the same weights, so the output that used to sit at position i now sits at position π(i). Unmasked self-attention is equivariant to permutation. No index is read in the score.

### The causal mask makes a decoder order-sensitive

Decoder self-attention is different. A causal mask adds negative infinity to score i,j when j is greater than i, so token i can attend only to j less than or equal to i. The mask depends on i and j, so permuting tokens changes which pairs are allowed. A three-token example makes the break visible. Use scalar queries q=(1,2,3), keys k=(1,0,1), and values v=(10,20,30). Without a mask, token 2 scores against all keys as (2,0,2); softmax gives (0.468,0.063,0.468) and output 19.98. With a causal mask, token 2 sees only keys 1 and 2, scores (2,0); softmax gives (0.881,0.119) and output 11.19. Move token 2 to first position and the allowed set changes again. The bag-of-tokens claim holds only for unmasked attention. A decoder is order-sensitive by construction.

The consequence is blunt for a transformer with no positional signal and no mask. It sees a bag of tokens. "Dog bites man" and "man bites dog" are the same input to it. Word order has to be inserted deliberately, and the four generations of doing that insertion explain a surprising amount of how modern models behave at long context.

### Sinusoidal encodings and the offset property

The first generation is the sinusoidal encoding of Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser and Polosukhin, published as "Attention Is All You Need" in 2017. For dimension pair i and position p they set one slot to sin(p / 10000^(2i/d)) and the next to cos of the same argument. The wavelengths form a geometric ladder. The fastest pair completes a full cycle every 2π positions; the slowest takes roughly 10000·2π. The design has a property worth pausing on. Because sin(a+k) equals sin a cos k plus cos a sin k, and cos(a+k) equals cos a cos k minus sin a sin k, the pair at position p+k is the pair at p multiplied by the matrix [[cos k, sin k], [-sin k, cos k]]. For k=1 and p=1, the pair (sin 1, cos 1) is (0.841,0.540); the matrix [[0.540,0.841],[-0.841,0.540]] gives (0.908,-0.415), which is (sin 2, cos 2). The map depends only on k. A linear projection inside the attention layer can therefore learn to compare tokens by offset rather than by absolute address. The property gives a route, not a guarantee. The projections are fit on a finite range; at longer positions the phase pattern enters combinations not present in training, and high-frequency pairs wrap many times. The original paper trained and tested within a fixed range, so the property was a hope rather than a demonstrated long-context result.

### Learned tables and relative position biases

The second generation dropped the sinusoids for a lookup table. BERT (Devlin, Chang, Lee and Toutanova, 2018) and GPT-2 (Radford, Wu, Child, Luan, Amodei and Sutskever, 2019) learned one vector per position and added it to the token embedding. This works well inside the training length. At position 1025 in a table built for 1024 positions there is no row. Clamping reuses a trained row, typically the last one, at an untrained position; inventing a row feeds a vector the model never trained on. Either way, the model sees a position encoding outside its training distribution A learned table also entangles where a token is with what it is. The same word at position 5 and position 500 arrives at the first layer wearing different vectors. Because the position vector occupies the same dimensions as the token embedding, downstream layers that need position-invariant content must disentangle it from position; layers can also use the entangled signal, so this is a capacity trade-off rather than a hard requirement

The third generation made position relative. Shaw, Uszkoreit and Vaswani proposed relative position representations in 2018, adding a learned vector indexed by the clipped offset i−j to each key before the dot product. The score becomes q_i · (k_j + a_clip(i−j,−k,k)), which equals q_i · k_j plus q_i · a_clip(i−j,−k,k). Offsets beyond the maximum distance k share the same vector. Transformer-XL (Dai, Yang, Yang, Carbonell, Le and Salakhutdinov, 2019) built a similar bias out of sinusoids. The extra term is computable. It is not a plain q·k product, so you cannot fold the whole thing into one matmul over cached keys. A cached key vector no longer suffices because the same key needs a different added term for every query position. For a new query i, the q_i·k_j scores are one matmul over cached keys, but the relative term needs q_i·a_{i−j} for each j. Naively that is O(nd) multiply-adds; with clipped offsets there are at most 2k+1 distinct a_r, so you can compute q_i·a_r for all r in O(kd) as a separate matmul against the relative-embedding table, then add the appropriate scalar bias to each of the n scores in O(n). So the whole score is not one matmul over cached keys alone

### Rotary position embedding and the scaling knob

Rotary position embedding arrived in April 2021 from Jianlin Su and colleagues, in "RoFormer: Enhanced Transformer with Rotary Position Embedding". It applies a rotation instead of an addition. Take the query and key vectors, split them into pairs of dimensions, and for pair m rotate the two components by an angle proportional to position, with frequency θ_m = 10000^(−2m/d). Do the same to the key at its own position. Consider one pair with frequency θ. A query whose unrotated value is (1,0), sitting at position i, becomes (cos iθ, sin iθ). A key with the same unrotated value at position j becomes (cos jθ, sin jθ). Their dot product is cos iθ cos jθ plus sin iθ sin jθ, which is cos((i−j)θ). The absolute positions vanished. For general q and k the pair dot is a linear combination of cos and sin of (i−j)θ, still a function of offset alone. The full dot product is a sum over pairs of linear combinations of cosines and sines of the offset at a spread of frequencies Position enters the score as a function of distance and nothing else.

Press, Smith and Lewis published ALiBi in 2021, in "Train Short, Test Long". ALiBi adds no positional vector at all. It subtracts a penalty proportional to distance from the attention score, m_h·|i−j|, with a different slope m_h for each head. For n heads, m_h = 2^(−8h/n) for h from 1 to n. For 8 heads the slopes are 1/2, 1/4, 1/8, 1/16, 1/32, 1/64, 1/128 and 1/256. The sequence is geometric because each head's penalty slope sets its effective range, and multiplicative spacing covers a log scale. A head with m=1/2 drops a score by 0.5 per token of distance; at 100 tokens the penalty is 50. A head with m=1/256 drops 0.39 at 100 tokens. Softmax turns that into near-zero weight for far tokens in fast-decay heads. Because the penalty grows linearly, far scores go to negative infinity; there is no periodic ambiguity. That is why ALiBi avoids RoPE's unscaled long-range failure.

RoPE became the default for mechanical reasons. The rotation is applied to the query and key once, at the moment they are produced, so the cached key is already rotated and the cache stays an ordinary matrix. It adds no parameters. And it exposes a knob, the base 10000, which turns out to be tunable at inference time. ALiBi is simpler and extrapolates more gracefully out of the box; its fixed linear decay does not blow up past the training length the way an unscaled rotation does. But ALiBi offers no equivalent knob. By early 2023 LLaMA (Touvron, Lavril, Izacard and colleagues) had adopted RoPE, many derivative models followed, and kernel libraries standardised around it. Adoption is evidence about tooling and pretrained weights, not proof RoPE is better at every length.

The knob is where the modern story lives. If you want a model trained on a shorter window to handle a longer one, the naive fix is position interpolation, published by Chen, Wong, Chen and Tian in 2023. Divide every position by a scale factor s so the extended sequence occupies the same angular range the model was trained on. It works, but with a cost. Take a training length L=1024 and a token at p=2048, with s=2. The interpolated position is 1024. For θ=0.01, the angle goes from 20.48 radians to 10.24 radians. Adjacent long-range tokens p=2048 and p=2049 become 1024 and 1024.5, so the angle gap is 0.005 instead of 0.01. Low-frequency dimensions lose the resolution that distinguishes them

NTK-aware scaling, circulated by bloc97 in 2023 as a community post rather than a paper, fixes that by changing the base instead of the positions. Raise the base and the frequency ladder stretches unevenly. The formula is b' = b·s^(d/(d−2)). For d=128 and s=2, the exponent is 128/126=1.016, so b'=10000·2^1.016=20220. The per-frequency effect is θ_m' = b^(−2m/d)·s^(−2m/(d−2)). The fastest dimension m=0 stays at θ=1. The slowest pair m=63 goes from 10000^(−126/128)≈1/8660 to about 1/17320. Fast dimensions barely move; slow ones stretch a great deal.

YaRN (Peng, Quesnelle, Fan and Shao, 2023) refined this into a per-dimension ramp between interpolated and extrapolated behaviour. Let λ_m=2π/θ_m and r_m=L/λ_m. With α=1 and β=32, the ramp is γ_m=clamp((r_m−α)/(β−α),0,1). When γ_m=0 the dimension is interpolated; when γ_m=1 it is extrapolated; values between blend the two angles. YaRN also adds a temperature correction on the attention logits because stretching changes the entropy of the softmax. The correction is t=0.1·ln(s)+1, and the logits are multiplied by 1/sqrt(t). For s=2, t=1.069 and the scale is 0.967. For s=8, t=1.208 and the scale is 0.910.

What breaks when you stretch is easiest to see in the slowest dimensions. Those pairs complete less than one full rotation across the training window. Push past it and two positions far apart map to nearly the same angle, so the model cannot separate them in that subspace. The fast dimensions keep working, which is why extended models still produce fluent local text while quietly losing the ability to track a fact from the beginning of a long document. No amount of rescaling creates information the model never learned.

### KV cache memory and admission

Positional encoding sets what the model can distinguish. The KV cache sets what you can afford to store. A KV cache stores key and value vectors for past tokens so decode does not recompute them. Memory scales with positions. In general, KV bytes equal 2 × layers × kv_heads × head_dim × dtype_bytes × positions divided by tensor_parallel. The factor 2 is K and V; layers, kv_heads, head_dim and dtype set bytes per position; tensor parallel divides the cache across ranks. On the measured engine, the serving pool holds 262,144 positions against a native window of 1,048,576. Raising the pool to the full window costs about 0.68 GiB per rank. The arithmetic uses the config figure of 0.9 GiB per 1,048,576 positions per rank. Extra positions are 1,048,576−262,144=786,432. The fraction is 786,432/1,048,576=0.75. Extra memory is 0.9×0.75=0.675 GiB, rounded to 0.68 GiB per rank.

Admission reserves space before a request runs. With 4 streams, the equal share of the pool is 262,144/4=65,536 positions. The default reply budget is 32,768 tokens, the decode round batch width is 16 rows, and two rows are reserved. The per-stream ceiling is 65,536−32,768−16−2=32,750 tokens. If the pool were raised to 1,048,576, the share would be 262,144 positions per stream, and the ceiling would be 262,144−32,768−16−2=229,358 tokens.

On the measured pair the engine holds 111.5 GB of unified memory, with LPDDR5X at 273 GB/s shared by CPU and GPU. Under load the SM clock reads 2,197 MHz against a 3,003 MHz ceiling. Single-stream decode is 59.1 tok/s; four concurrent streams aggregate 106.2 tok/s, a 1.80x multiplier. Prefill runs at 39,237 tok/s over 98 requests. Prefix caching covers 95.9% of prompt tokens, which removed 313 s of prefill. Draft acceptance is 67.6%. Mean time to first token is 3.46 s, mean prefill 3.33 s, and mean decode 8.38 s. The sampled requests average 130,659 prompt tokens and 607 generated tokens. Pair stall has accumulated 120,000 ms, and memguard kills a rank below 2.5 GiB available.

At 262,144 positions the pool is 786,432 positions short of the native window, and closing that gap costs 0.675 GiB per rank.
