## Not every token needs to see every token

A request lands with a long prompt. Somewhere near the beginning is a clause the user cares about. The model generates an answer one token at a time. For each generated token, full attention compares it against every prompt token and every token generated so far. That is the baseline, and it is expensive.

On the machine from the previous chapters, the 98-request window recorded by the tensorfold request_latency_seconds_count metric contains 12,804,579 prompt tokens. Divide by 98 and the mean prompt length is 130,659 tokens. At that length, the causal mask leaves n(n+1)/2 query-key pairs, where n is the prompt length. For n=130,659, that is 130,659 times 130,660 divided by 2, or 8,535,952,470 pairs. Each pair is a dot product of a query vector and a key vector. The scores go through a softmax, and the result weights a sum of value vectors. The previous chapter explained that writing the attention matrix to memory and reading it back is the bottleneck. Sparse attention reduces the number of scores computed and the number of keys read. The prefix cache saves work when two requests share a prefix. Sparse attention saves work within a single request by reducing the keys each token reads.

Sparse Transformer, by Child, Gray, Radford and Sutskever in 2019, factored attention into local and strided patterns. The design bet was that many of the n squared interactions carry little information. A token needs its neighbors and a few long-range connections, but it does not need every other token. Longformer, by Beltagy, Peters and Cohan in 2020, turned that idea into a practical encoder. It combined a sliding window, dilated windows, and global tokens.

The sliding window is the simplest. Each token attends to a fixed number of previous tokens. In a causal model, token i attends to the W positions ending at i. The cost per token is W instead of n. Take n=130,659 and W=4,096. At the last position, full attention reads 130,659 keys. The window reads 4,096 keys. Over the whole prompt, full causal attention has 8,535,952,470 pairs. A sliding window has at most n times W pairs, or 130,659 times 4,096, which is 535,179,264 pairs. The ratio is 8,535,952,470 divided by 535,179,264, or about 16. The window caps each token's read at W, so the total cost grows linearly with n instead of quadratically.

Stack the layers and the receptive field grows. With a window of W positions including the current one, one layer lets token i see i-W+1 through i. Two layers let token i see the union of the windows around those positions, which reaches back to i-2W+2. After L layers, the earliest visible position is i-L(W-1). The receptive field size is L(W-1)+1. Take W=4,096 and L=32. The receptive field is 32 times 4,095 plus 1, or 131,041 positions. That is enough to reach the start of a 130,659-token prompt from the end. The path is indirect. A token at position 1 reaches the final token through a chain of 32 attention operations. At each layer, the representation of the earlier token is mixed with up to 4,095 other tokens by a softmax that sums to one. The final hidden state can carry a compressed trace of the clause, but it has no addressable slot for the exact string. A name or a number that appears once is averaged with everything else along the path. The residual stream keeps the token's original embedding, but later layers add updates to that stream, and the exact key-value pair from the first layer is not stored as a lookup key in the final layer.

Longformer added two refinements. A dilated window attends to every d-th token in a wider span. With 4,096 scores and dilation 2, the window covers 8,191 positions. A dense window with 4,096 scores covers 4,096 positions. The score count is the same, and the span doubles. Global tokens are a few positions that attend to every token and are attended by every token. Longformer marks task-specific positions as global, such as the classification token or the question in a question-answering task. BigBird in 2020 adds random attention edges alongside the same global-token pattern; the global tokens themselves are fixed or task-specific, not randomly selected. Training includes the global attention mask, so gradients flow through the global token. The global token gives every position a two-hop path to every other position: position → global token → other position That path passes through the global token's hidden state, which is a weighted sum of values. It is not a copy of each key-value pair. The graph is connected, and the information is lossy. With g=4 global tokens and n=130,659, the extra dense component is about 2 times g times n, or 1,045,272 pairs. That is about 0.012 percent of the causal full count. The cost is small. The benefit is a direct path. The cost in information is that the global token carries a summary.

Attention sinks are a separate mechanism. StreamingLLM, by Xiao and colleagues in 2023, found that a pure sliding window fails when it evicts the first few tokens. The softmax has to sum to one. If no key is strongly relevant, the model needs a place to put the remaining probability mass. Initial tokens often receive high attention regardless of semantic content. Because softmax must sum to one, the model can dump leftover probability mass on them. They need not be identical across sequences or semantically empty; the sink is an empirical behavior, not something learned from their stability You can see the effect in a toy softmax. Suppose a query has scores 4.0 for the sink key, 2.0 for a relevant key, and 1.0 for an irrelevant key. The exponentials are 54.598, 7.389, and 2.718. The sum is 64.705. The sink gets 54.598 divided by 64.705, or 0.844. The relevant key gets 0.114. The irrelevant key gets 0.042. Remove the sink key and the softmax runs over 2.0 and 1.0. The sum is 10.107. The relevant key gets 0.731, and the irrelevant key gets 0.269. The attention mass redistributes. The sink key matters because it holds the denominator open. Its value matters less if the sink's value vector is near zero or if later layers ignore it. You can separate the roles with a diagnostic. Keep the sink key but set its value to zero. The denominator still includes the sink, so the relevant key keeps 0.114 of the mass. Remove the sink key but keep its value. The value is never read because the key is gone. The first case changes the content added. The second changes the normalization. StreamingLLM reported that keeping a small number of initial tokens plus the recent window recovered the full-cache perplexity on their streaming benchmark. The fix follows from the softmax. The sink keys keep the denominator close to what the model saw in pretraining.

Mistral 7B in 2023 applied sliding window attention in every layer and used a rolling buffer for the KV cache. The cache holds only the last window of keys and values. Mistral 7B’s fp16 KV cache is about 128 KiB per token (32 layers × 8 KV heads × 128 dim × 2 for K/V × 2 bytes). A 4,096-position window therefore needs about 512 MiB of KV cache per stream The rolling buffer is a circular array. For token i, the slot is i modulo W. The attention mask maps logical positions to slots. When the buffer wraps, the kernel must gather the valid slots in order and mask the rest. Position IDs are absolute, not slot indices. With rotary position embeddings, the dot product between query i and key j depends on i-j. If you renumber positions after eviction, the model sees a different relative distance. The rolling buffer keeps the original position IDs so the rotation stays consistent. Sparse attention and KV eviction are different. Sparse attention changes the score matrix. A block-sparse kernel can skip reads from a full cache. KV eviction deletes entries from the cache. The first preserves the option to read old keys if a later query needs them. The second does not. Mistral combines a local attention pattern with a rolling buffer, so the score matrix is sparse and the cache is evicted. The model computes a softmax over the window, so the attention distribution is normalized over a smaller set. In Mistral

The pool on the machine shows the scale. The shared KV pool is 262,144 positions across four streams. Four streams means four concurrent request slots, set by PARALLEL=4 and TF_DS_STREAMS=4 in the live container. The equal share per stream is 262,144 divided by 4, or 65,536 positions. Admission overhead reduces that. The live formula is POOL divided by PARALLEL, minus MAX_TOKENS, minus ROUND_ROWS, minus 2. MAX_TOKENS is 32,768, the default reply budget when a request names none. ROUND_ROWS is 16, the decode round batch width. The two guard positions are part of the admission code. For the current pool, 65,536 minus 32,768 minus 16 minus 2 is 32,750 positions per stream. Full causal attention over 65,536 positions has 65,536 times 65,537 divided by 2, or 2,147,516,416 pairs per stream. Across four streams, that is 8,590,065,664 pairs. A 4,096-position sliding window over the same 65,536 positions has at most 65,536 times 4,096, or 268,435,456 pairs per stream. Across four streams, that is 1,073,741,824 pairs. The window cuts the pair count by about 8 times. The arithmetic is the argument for sparsity. The question is whether the discarded pairs mattered.

Hybrid layers mix local and full attention. Gemma 2 in 2024 alternated sliding-window layers with full-attention layers. The full layers give every token a direct edge to every other token. The local layers keep most of the cost down. Take L=32 layers, half local and half full, with W=4,096. At the last token, a full layer reads 130,659 keys. A local layer reads 4,096 keys. The 16 full layers cost 16 times 130,659, or 2,090,544 key comparisons. The 16 local layers cost 16 times 4,096, or 65,536. The total is 2,156,080. All 32 full layers would cost 32 times 130,659, or 4,181,088. The hybrid is 2,156,080 divided by 4,181,088, or 51.6 percent of the full cost. The full layers are arranged every few layers, and training uses the same pattern. A full layer gives a direct edge from query i to key j, so the exact key-value pair is available at that layer. The architecture removes the information bottleneck that a pure local stack imposes, though it does not guarantee that the model learns to use the edge. For retrieval, that edge is the difference between reading the clause's key and reconstructing the clause from a summary.

Implementation matters. A GPU attention kernel tiles queries and keys. It loads blocks of keys and values from high-bandwidth memory into shared memory, computes the query-key products for the tile, updates the online softmax running max and denominator across live key blocks, and accumulates the weighted value block; final normalization happens after all live key blocks are processed. Full attention reads every key-value block for every query block. A block-sparse pattern marks some blocks as entirely masked. The kernel skips those blocks. It does not load their keys and values from memory, does not compute their query-key products, and does not include them in the softmax denominator. That is how fewer scores become fewer memory reads. The pattern has to align with the kernel's block shape. If the mask is irregular, the kernel may still load a full block or use a gather, and the memory saving shrinks. Coalesced loads want contiguous blocks. A sliding window is contiguous, so it maps well to block masks. A strided or dilated pattern is less contiguous, so it may need a different kernel or a gather. FlashAttention tiles the attention computation and avoids materializing the full score matrix, but it still reads all keys and values. A sparse kernel skips tiles. The two techniques compose. The sparse mask decides which tiles are live, and the tiled kernel computes only those tiles.

Evaluation separates two questions. Language modeling asks whether the next token is predicted well. Retrieval asks whether an exact string from a distant position can be recovered. A sliding-window model can have low perplexity on ordinary prose and still fail a needle-in-a-haystack test that asks for a clause beyond the window. The two metrics test different paths through the computation graph. Perplexity mostly exercises local continuation. Retrieval exercises the direct edge from the question token to the clause token. If no layer provides that edge, the answer must come through hidden-state summaries. A summary often preserves the gist of the clause but not the exact string; residual connections can in principle carry token identity along indirect paths, so exact copying through summaries is possible but generally unreliable That is why a hybrid with at least one full layer is a different architecture from a pure sliding window, even when most layers are local.

For the 130,659-token prompt, the question token at position 130,659 needs an edge to the clause at position 1. In a pure sliding-window model with W=4,096 and L=32, the edge exists only through 32 layers of averaging. The receptive field reaches the clause, but the path is indirect. In a hybrid with one full layer, the edge exists directly at that layer. The difference is whether the key-value pair for the clause is read by the question's query at some layer. If it is, the model can copy the exact string. If it is not, the model can only use what survived in the hidden states. That is the test to run on a long-context model. Find the layer where the question token's query reads the clause token's key. If no such layer exists, the model must rely on indirect, multi-hop propagation through intermediate hidden states. That path can sometimes carry exact strings, but it is less reliable and often degrades to gist-level summarization. So the direct-edge test is strong evidence for retrieval, not a proof against it
