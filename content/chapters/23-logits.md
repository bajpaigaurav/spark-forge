## From a vector to a word

In 2003 Yoshua Bengio, Réjean Ducharme, Pascal Vincent and Christian Jauvin published "A Neural Probabilistic Language Model". They replaced n-gram lookup tables with a dense vector for context, multiplied that vector against a matrix with one row per vocabulary word, and turned the scores into a probability distribution. The output matrix and the softmax that follows it remain the final stage in the standard decoder-only transformer language model. Variants exist. Sampled softmax handles large vocabularies by scoring a subset of candidates, mixture-of-experts architectures change where parameters sit, and some models replace softmax with other normalizers. The core pattern is still a vector multiplied by a vocabulary-sized matrix and normalized into probabilities. Two decades of work changed what produces the vector. The final readout has changed less than the blocks that produce it.

A decoder-only transformer processes a sequence through blocks. Each block reads a residual stream, runs attention over earlier positions, applies a feedforward update, and writes back into the stream. The residual stream is a vector per position, and its width is d_model. Attention lets a position mix information from previous positions. By the time the final block finishes, the stream holds a vector at the last position. Call it h. For a batch of B sequences with T positions, the final hidden states form a B by d_model matrix after selecting the last non-padding position of each sequence. The head is a matrix W with V rows and d_model columns, where V is the vocabulary size. Most modern heads omit a bias. If one is present, it is a vector b of length V. The logits are s = h W^T, a vector of length V. For batch input, the same product gives a B by V matrix. Row w of W is a direction in the same d_model space as h. The dot product h·W_w measures how far h points along that direction.

Training shapes those directions through cross-entropy. For a target token y, the loss is L = -log p_y = -s_y + log Σ_j exp(s_j). The derivative with respect to logit s_j is p_j - 1[j=y]. With rows W_j, the derivative with respect to W_j is (p_j - 1[j=y]) h. The derivative with respect to h is Σ_j (p_j - 1[j=y]) W_j. A gradient step with learning rate η changes W_y by η(1-p_y)h when y is the target. That step moves row y toward the hidden state that predicted it. Non-target rows move away from h by η p_j h. The same step moves h toward W_y and away from the other rows. Over many examples, row y becomes aligned with the hidden states that tend to precede token y. A token scores high because its row points along the direction the model has learned to write when that token should come next. The head is a set of directions. Training sets them, and grammar or facts live in the residual stream that produces h.

The row count is fixed by the tokenizer before training begins. Byte-pair encoding, applied to machine translation by Sennrich, Haddow and Birch in 2016, starts from characters and repeatedly merges the most frequent adjacent pair. SentencePiece, from Kudo and Richardson in 2018, applies a similar merge or unigram model to raw text, uses a marker for spaces, and can fall back to bytes for unseen characters when byte fallback is enabled; otherwise they map to an unknown token. Both produce a fixed list of token IDs. Special tokens such as beginning-of-sequence, end-of-sequence, padding, and chat markers occupy their own rows. Row i of W corresponds to token ID i. Swapping tokenizers changes the segmentation and the ID-to-string mapping, so row i no longer means the same token. The embedding matrix must be rebuilt: rows for tokens shared with the old vocabulary can be copied over by token string, new rows must be initialized, and the model usually still needs retraining or fine-tuning because the new vocabulary changes the input distribution, and the model usually needs retraining or fine-tuning because the new vocabulary changes the input distribution. A model can be retrained. A vocabulary is a commitment.

The matrix is often tied to the input embedding. Press and Wolf made the case in 2016 in "Using the Output Embedding to Improve Language Models". Let E be the input embedding matrix, also V by d_model. If W is tied to E, then the score for candidate w is h·e_w. The same vector e_w is written into the residual stream when w appears as input and read out as a direction when w is a candidate output. Training therefore shapes one set of vectors to serve both roles. The geometry here is the arrangement of token vectors in d_model space. Angles and distances between e_w and e_v determine both how the model represents input tokens and how it scores output tokens. With separate matrices, input rows and output rows can settle into different arrangements. With tied rows, the two roles share one arrangement, and the gradient to e_w receives contributions from both the input lookup and the output head. Press and Wolf reported perplexity improvements in their experiments. The choice remains architecture-specific. The parameter saving is concrete. Take V = 50,000 and d_model = 4,096. The head alone has 50,000 × 4,096 = 204,800,000 parameters. Tying removes that entire block from the parameter count, about 205 million parameters.

Logits are unbounded real numbers. Softmax exponentiates each score and divides by the sum. Suppose the head returns three scores, 2, 1, and 0. The exponentials are e² ≈ 7.389, e ≈ 2.718, and 1. Their sum is about 11.107. The probabilities are about 0.665, 0.245, and 0.090. Shift all three scores down by 2 and the distribution is identical because the same factor cancels from every term. Only the gaps between scores matter. Exponentiation makes every score positive and exaggerates differences. A gap of one in logits becomes a factor of e in probability space. A gap of ten becomes e¹⁰, about 22,026 to 1. Implementations subtract the largest logit before exponentiating. That leaves the distribution unchanged and keeps the exponentials from overflowing.

The head has a concrete arithmetic cost. For each token, the matrix-vector product h W^T performs d_model × V multiply-adds, or 2 d_model V FLOPs, before the softmax normalizer. At d_model = 4,096 and V = 50,000, this gives 204,800,000 multiply-adds per token. A transformer layer at the same width with a 4d feedforward block performs about 12 d_model² multiply-adds in its linear projections, which is about 201,300,000. The head is comparable in arithmetic to one layer. Its parameter count is also comparable. In small models with large vocabularies, the head can be one of the largest parameter blocks. In large models with small vocabularies, it can be smaller than a layer. The comparison is d_model V against the layer's 12 d_model². Weight tying is attractive because it removes the head's parameter block without removing its arithmetic.

Temperature acts on the softmax after the head has produced its scores. Dividing every logit by T rescales all gaps at once. Take the same three logits, 2, 1, and 0. At T = 0.5, the scaled logits are 4, 2, and 0. The exponentials are about 54.598, 7.389, and 1. Their sum is about 62.987. The probabilities are about 0.867, 0.117, and 0.016. At T = 2, the scaled logits are 1, 0.5, and 0. The exponentials are about 2.718, 1.649, and 1. Their sum is about 5.367. The probabilities are about 0.506, 0.307, and 0.186. A temperature below one sharpens the distribution toward its argmax. A temperature above one spreads mass into the tail. Temperature cannot recover a candidate the head scored far below the top. It can only reweight what the head already produced.

Hinton, Vinyals and Dean made the training-side argument in their 2015 preprint "Distilling the Knowledge in a Neural Network". A teacher's distribution at temperature one is nearly one-hot, so most of the information about which wrong answers are plausible sits in probabilities too small to train against. Raising the temperature softens the distribution until those small probabilities carry gradient. The student is trained with a KL divergence between temperature-scaled teacher and student distributions. Write the teacher's scaled distribution as p_i^T = exp(z_i/T) / Σ_j exp(z_j/T) and the student's as q_i^T = exp(v_i/T) / Σ_j exp(v_j/T). The loss is L = T² Σ_i p_i^T log(p_i^T / q_i^T). The T² factor compensates for the 1/T inside the softmax derivative. The gradient with respect to a student logit v_i is T (q_i^T - p_i^T). At high temperature, q_i^T - p_i^T is small, and the T factor restores a finite gradient. The small teacher probabilities carry information about relative similarity among wrong classes. If the teacher's tail is noise, distillation can transfer that noise. The method depends on the teacher's tail being informative, and that is an empirical property of the teacher, not a guarantee.

Decoding turns the distribution into a token. Greedy decoding takes the argmax. Top-k decoding keeps the k highest-scoring candidates, sets the rest to zero, and renormalizes. Top-p decoding, also called nucleus sampling, sorts candidates by probability, keeps the smallest set whose cumulative probability reaches p, and renormalizes that set. Temperature sampling divides the logits by T before the softmax and draws from the resulting distribution. These methods differ in how much of the tail they admit. Greedy admits none. Top-k admits a fixed count. Top-p admits a variable count that depends on the shape of the distribution. Temperature changes the shape before any cut. The next chapter takes up the choice among them.

A hallucination can arise from a small logit margin. Suppose the correct fact has logit 5 and a fluent generic continuation has logit 6, with 100 other candidates at logit 0. The exponentials are about 148.4, 403.4, and 100. The sum is about 651.8. The generic token gets about 0.619, the correct token about 0.228, and the rest about 0.153. Greedy decoding picks the generic token. A top-p cut of 0.6 keeps only the generic token because its probability already exceeds the threshold, and the correct token is removed. The softmax has converted a one-point logit gap into a 2.7-to-1 probability ratio, and the tail has swallowed the fact. This is a mechanism. It does not diagnose every hallucination. The point is that a weak direction for a rare fact can lose to a strong direction for a fluent continuation, and the decoding rule can finish the job.

Repetition can arise through attention and the KV cache. During decode, the model computes a hidden state for the current position by attending over previous positions. The previous token's key and value are in the cache. If attention weights on that token are high and the surrounding context supplies no stronger signal, its value vector enters the residual update and can dominate the hidden state. The head row for that token was trained to align with hidden states that precede it, so the dot product is large. Softmax concentrates probability on the same token. The token is emitted, appended to the cache, and the next step can retrieve it again. A repetition penalty edits the logits before normalization. One subtractive form sets s'_i = s_i - δ for tokens already present and s'_i = s_i otherwise. Take logits 2, 1, and 0 for tokens A, B, and C. Suppose A and B are already present and δ = 1. The edited logits are 1, 0, and 0. The exponentials are about 2.718, 1, and 1. The sum is about 4.718. The probabilities are about 0.576, 0.212, and 0.212. Before the penalty, the probabilities were about 0.665, 0.245, and 0.090. The penalty lowers the repeated tokens and raises the unseen one. Multiplicative penalties divide positive logits and multiply negative ones, which has a similar effect with a different scale.

The KV cache exists because decode would otherwise recompute attention keys and values for every previous token at every step. It stores those tensors per layer. It does not store head logits or softmax outputs. During prefill, a request's prompt is processed in one pass. Attention over the prompt is computed in parallel, and only the final position's logits are needed for the next token, so the head is applied once per request. During decode, the head runs once per decode step—one fewer than the generated-token count, because the first token’s logits come from prefill. Attention during decode reads the cached keys and values and costs O(n d_model) per layer per token for the query-key product and value sum, where n is the current context length. The head costs O(d_model V) per token. The relative cost depends on n, d_model, and V. In the sampled window on the machine this book was written against, the tensorfold metrics counted 98 requests, 12,804,579 prompt tokens, and 59,476 generated tokens. Dividing gives 130,659 prompt tokens and 607 generated tokens per request on average. The head ran 607 times for the average request while the prompt was consumed in one prefill pass. That count shows the invocation asymmetry. It does not by itself prove that the head dominates cost, because the attention work and the head work scale with different variables.

The head is a fixed interface. It maps a d_model vector to V scores, and its matrix has d_model × V parameters. That can be a large block, sometimes comparable to a transformer layer and sometimes larger. The real constraint is readout. Everything the model has built in the residual stream must be legible through one linear map and a softmax. Whatever the model knows about syntax, arithmetic, or reference has to become a direction before the softmax can act on it. The softmax is where the model commits. Before it, the vector could still support many continuations. After it, there is a distribution, and a decoding rule has to choose. The next chapter takes up that choice.
